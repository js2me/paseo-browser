Paseo Browser runs a shared Chrome browser per workspace and displays its live pages inside Paseo on desktop, web and mobile. People and agents use the same pages, cookies and logins. Each viewer selects tabs independently. One participant controls a tab at a time; an agent cannot take control from a human.

Agents receive 11 tools for shared-browser status, captures, tabs, navigation, input and control handoff, plus 35 Chrome DevTools tools for accessibility snapshots, forms, JavaScript, uploads, screenshots, network requests, console, emulation and performance. Both sets operate on the workspace's Chrome. Agents can import/export and manage HttpOnly and Secure cookies, send arbitrary Chrome DevTools Protocol commands, and read protocol events for network interception, debugger, permissions and storage. Chrome validates protocol and cookie rules. DevTools requires exclusive workspace control and refuses calls while another participant controls any tab. Calls finish before a queued human takeover is applied, with a 20-second tool timeout.

A running browser in the displayed workspace automatically opens in the Explorer side panel beside the conversation. The workspace header button and Open Workspace Browser command reopen it manually. Closing the panel is respected for the rest of that browser session. Open browser sessions also appear in a sidebar item and composer pill. Desktop controls support mouse and keyboard; compact layouts support touch, text composition and mobile emulation presets. Display options include fit, actual size, viewport sizing, capture density and quality. Images stream through the daemon; encoded video is an optional host setting.

Workspace profiles live in the daemon's Paseo data directory. Logins survive panel closure, plugin reload and browser restarts. Closing a panel keeps Chrome running. Closing a browser or archiving its workspace stops the browser and retains its profile. Multiple clients connected to that daemon can view and control the shared workspace browser.

Requires Paseo 0.15.0 or newer and Node.js 24 or newer on the daemon host. Preparation uses installed Chrome on supported Linux/macOS paths when available, or downloads Chrome for Testing. Linux ARM64 needs a native non-Snap Chromium. Browser execution and website traffic remain on the daemon machine, including when viewing from a phone.

Chrome settings also retain separate browsers per agent, connection to your running Chrome 144+ after enabling remote debugging, and a debugging-endpoint mode. These standalone modes expose DevTools independently of the workspace panel. Existing saved connection settings are preserved. Save and reload this plugin to apply mode changes to existing sessions on their next idle prompt. Codex, Claude Code, Copilot and OpenCode are enabled by default; an agent label `paseo-browser/enabled=false` excludes that agent.

MCP usage statistics and CrUX reporting are disabled. Website data and existing accounts in a connected personal Chrome are accessible to the agent. Panel clipboard synchronization, native download/upload dialogs, media permissions, extensions and passkeys are not provided. Agents can upload files through DevTools. File tools access the MCP runtime's configured working directory. Workspace browser code is adapted from the MIT-licensed Shared Browser plugin with attribution included.

Preparation installs a short browser-routing skill into the daemon user's agent skills directory, with a Codex link. Both MCP adapters advertise usage instructions, and newly created supported agents receive conditional browser-routing guidance in their saved system prompt. This helps agents choose Paseo Browser instead of an unrelated CUA connection. Existing user-authored skills are preserved.
