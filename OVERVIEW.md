Paseo Browser gives a workspace a native Chromium browser on Paseo Desktop and broadcasts that same browser to mobile clients. Desktop input, scrolling and page rendering run directly in the WebView. The phone receives a bounded MJPEG stream of the same guest, cookies and page state. No second browser is opened for the phone.

Native mode requires Paseo Desktop to stay running. The desktop panel can be closed while a mobile viewer is connected; its native guest remains parked and shared. Broadcast capture starts only while remote viewers are watching and stops after they leave. A workspace supports up to eight native tabs. Participants take and release control; an agent cannot take control from a human.

The plugin includes a desktop bridge update for native capture, CDP commands and protocol events. Its preparation tool makes a separate Linux desktop copy and preserves the installed application. Existing clients without the bridge show an update message. Source patches are included for building Paseo on other platforms. Activating the prepared desktop requires closing the original app and starting the prepared copy.

Agents can navigate, use accessibility snapshots, fill forms, upload files, run JavaScript, inspect console/network activity, manage cookies including HttpOnly and Secure, and send CDP commands. Native tabs use Paseo's existing browser profile, so cookies and logins are shared with its other native browser tabs. File uploads use files available on the desktop host. Browser-level commands cannot close or crash the Paseo application.

Legacy daemon-hosted Chrome remains available in settings, along with separate Chrome instances, connection to personal Chrome 144+ and debugging-endpoint mode. These modes are independent of the native browser. Saved connection settings are preserved. Codex, Claude Code, Copilot and OpenCode are enabled by default; the agent label `paseo-browser/enabled=false` opts out.

The native stream uses the selected desktop tab's viewport, with images bounded to 1280 × 960 and a requested polling cadence of about 15 FPS. Actual frame rate depends on the desktop, page and connection. Native iOS/Android clients display JPEG frames through their image component. Encoded H.264/VP8 remains optional in legacy mode. MCP telemetry and CrUX reporting are disabled. Legacy workspace code is adapted from the MIT-licensed Shared Browser plugin, with attribution included.
